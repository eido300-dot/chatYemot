# הוראות לאג׳נט מתקין

מסמך זה מיועד לאג׳נט עם גישה מורשית לשרת היעד. מטרתו התקנה ואימות של ChatYemot. המדריך הטכני והתבניות נמצאים ב־[ubuntu.md](ubuntu.md) וב־[`deploy/`](../deploy/).

## המשימה

התקן את `https://github.com/eido300-dot/chatYemot` מענף `main`. ודא שהגרסה כוללת את קומיט התיקונים `bbe2313`; אל תקבע אותו כגרסה אחרונה אם נוספו קומיטים. תעד את הקומיט שנפרס בפועל.

המשך עד להשלמת ההתקנה והאימות. פעולות התקנה שגרתיות והפיכות במסגרת המשימה מאושרות. אם חסרים דומיין, גישה נדרשת או החלטה שמשפיעה על אתר קיים, שאל שאלה ממוקדת והמשך בינתיים בעבודה שאינה תלויה בתשובה. אל תבקש אישור חוזר על פעולות שכבר אושרו.

## מידע לקבל לפני פעולה תלויה

- דומיין האתר ורשומות DNS, גישת SSH וסמכויות sudo.
- האם זו התקנה חדשה או עדכון, והאם Webmin/Nginx/Apache מנהלים את השרת.
- פרטי מסד קיימים אם ישנם, מנגנון סודות פרטי ויעד גיבוי מוגן.
- שם משתמש ושם תצוגה למנהל הראשון; מספר טלפון נדרש רק לשימוש בקו.

אל תבקש סיסמאות, PIN או מפתחות בצ׳אט. השתמש במנהל סודות או במסוף פרטי שאינו מוקלט.

## סדר עבודה

1. **גלה את מצב השרת.** בדוק מערכת הפעלה, גרסאות, משאבים, שירותים, פורטים, תעודות, אתרים והתקנות קיימות. קרא כל `AGENTS.md` שחל על הנתיבים. שמור שינויים מקומיים והגדרות קיימות.
2. **קרא את הפרויקט.** קרא `README.md`, `docs/ubuntu.md`, `docs/integrations.md`, `deploy/chatyemot.service`, `deploy/nginx.conf.example` ו־`.env.example`. אל תדפיס `.env` קיים.
3. **הכן גיבוי אם זו התקנה קיימת.** גבה יחד את MariaDB ואת `DATA_DIR` לאחר עצירת השירות, ושמור את `.env` בגיבוי סודות מוגן. תעד דרך חזרה לגרסה הקודמת.
4. **התקן דרישות וקוד.** נדרשים Node.js >=22.9.0 (מומלץ 24 LTS), MariaDB >=10.6, FFmpeg ו־Git. השתמש ב־`/opt/chatyemot` ובמשתמש שירות `chatyemot`. התקן באמצעות `npm ci --omit=dev`; אין שלב build.
5. **הכן מסד והגדרות.** צור מסד `utf8mb4` ומשתמש ייעודי המוגבל אליו. הגדר `.env` בבעלות משתמש השירות ובהרשאות `0600`, עם `NODE_ENV=production`, מקור HTTPS מדויק ו־`DATA_DIR=/var/lib/chatyemot`. צור את תיקיית הנתונים בבעלות משתמש השירות והרץ `npm run db:migrate` מתיקיית הפרויקט באותה סביבה.
6. **צור מנהל בהתקנה חדשה.** השתמש בכלי `npm run user` ובסודות פרטיים. סיסמה 12–256 תווים; PIN נפרד בן 6–12 ספרות למשתמש קו. אין חשבון ברירת מחדל.
7. **הפעל שירות יחיד.** לפני ההפעלה חסום גישה חיצונית לפורט 3000 ולמסד, תוך שמירת גישת SSH וגישה מקומית. התאם את תבנית systemd לנתיב Node בפועל ולשירות המסד, ודא שהמסד פעיל ובדוק את קובץ השירות עם `systemd-analyze verify`. הפעל מופע אחד בלבד כמשתמש השירות, עם עלייה אוטומטית באתחול. המתן ל־`/health` באמצעות ניסיונות מוגבלים; הפעלת systemd לבדה אינה מוכיחה שהאתר מוכן.
8. **הגדר HTTPS ורשת.** שלב reverse proxy בתצורת האתר הקיימת. בדוק תצורה לפני reload, שמור גישת SSH וחסום גישה חיצונית לפורט 3000 ולמסד. מנע רישום של נתיב `/ivr/` הסודי בכל שכבות הלוגים.
9. **אמת בפועל.** בדוק `/health` מקומית ודרך HTTPS, כניסה, טקסט, תגובה, עריכה, העלאת שמע, האזנה ויציאה. בדוק עצירת מיקרופון, restart ושמירת נתונים. ודא חסימת פורטים מבחוץ אם קיימת נקודת בדיקה חיצונית.

## מגבלות העבודה

- אל תמחק מסדים, קונטיינרים, volumes או נתוני משתמשים ואל תדרוס אתרים קיימים.
- אל תריץ את האפליקציה כ־root, ב־cluster או בכמה workers.
- אל תריץ בדיקות שרת/דפדפן מול הייצור או את `scripts/dev-db.sh` בשרת הייצור. בדיקות הפרויקט מיועדות למסד בדיקות נפרד ועלולות למחוק אותו.
- בהתקנה חדשה השאר `YEMOT_ENABLED`, `TZINTUK_ENABLED` ו־`TRANSCRIPTION_ENABLED` כבויים, ומפתחות VAPID ריקים. בהתקנה קיימת אל תשנה הגדרות אינטגרציה פעילות בלי לברר.
- אל תשלח צינתוק, פוש או בקשות לספקים חיים כחלק מההתקנה. הפעלת אינטגרציות היא משימה נפרדת עם בדיקת התור הקיים.
- אל תחשוף סודות בצ׳אט, בארגומנטים של פקודות, בהיסטוריה, בלוגים או ב־Git. אל תשנה את מאגר GitHub.

## דיווח סיום

הצג כתובת אתר וקומיט שנפרס, גרסאות ושירותים שהותקנו, נתיבי התקנה/נתונים/גיבוי ללא סודות ותוצאות האימות שבוצע בפועל. פרט מה לא אומת או נותר חסום, ומה נדרש להשלמה. צרף פקודות restart וצפייה בלוגים לפי המדריך. אם לא הייתה גישה לדפדפן או לבדיקת פורטים חיצונית, ציין זאת במפורש.
